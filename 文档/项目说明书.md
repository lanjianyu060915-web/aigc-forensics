# 项目说明书

说明这个项目是什么、这次做了哪些事情、现在能做到什么、还差什么。

## 一、这个项目是什么

把两个已有项目合并成一个面向图片和视频的 AIGC 检测与溯源系统（暂不含音频）：

- **换脸鉴伪系统（2.1 版）：** 有完整的桌面界面、人脸身份比对、原始素材检索和证据报告，但只会查换脸。
- **视频检测项目：** 有通用 AIGC 视频检测模型，但没有产品界面，也不支持溯源。

合并后，上传一张图或一段视频，系统给出分档的检测结论、三层来源线索和可校验的证据包。全程离线运行。

## 二、做了哪些事情

### 1. 建仓库，导入两个项目

新建公开仓库，换脸系统当外壳，保留原有目录结构。从视频项目裁出只含图片和视频推理的引擎（去掉音频、训练和外部平台代码），和原项目比对 4 条真实视频，分数最大差 2e-7。

### 2. 接入通用 AIGC 分支

引擎作为独立进程接入，常驻服务和单次运行共用一条路径，服务失败时自动回退到子进程。这个分支现在是总体结论的主要依据。

### 3. 新增文件标识解析

从零写了一个解析器，读取 GB 45438-2025 隐式标识、C2PA 容器结构、XMP DigitalSourceType 和生成工具痕迹，覆盖 JPEG、PNG、WEBP、MP4、MOV、MKV、WEBM、AVI 等容器，有 156 项测试和独立的结果页。在 1007 条真假视频上没有误报，但命中率低（10 条）。

### 4. 统一 CommunityForensics 的前处理

发现两个项目用的是同一份权重，但前处理不同：换脸系统没按作者的方式缩放和归一化。改成作者的前处理后，两边分数差 0.0，SWAN-DF 全部 AUC 从 0.897 升到 0.951，并重新定了边界。

### 5. 做交叉评测，改掉不可靠的整图分支结论

用换脸数据测通用分支，用普通视频测整图分支，发现两个重要问题：

- 通用分支对换脸基本没有区分力（DFDC AUC 0.541）。
- 整图分支的边界只适合高清人像：普通真实视频有 63–81% 会进高风险，DFDC 真人视频 AUC 只有 0.52。

原来系统的结论主要靠整图分支，这样下去大多数真实内容都会被标高风险。所以把它改成只作提示，不影响总体档位。

### 6. 新增人脸分支

换脸只改人脸区域，整图打分容易被背景稀释。用同一份 CF384 权重改打人脸裁剪图，案例 3 的 AUC 从 0.662 升到 0.895。视频直接复用抽帧时的人脸框。试过的 CLIP 线性头和“裁剪减整图”差值都不可移植，已否决。

总体规则改成：通用分支定主结论，人脸分支最多抬一级，整图分支只作提示。各路分数不相加。

### 7. 搭评测集，做盲测

| 评测集 | 规模 | 做法 |
| --- | ---: | --- |
| 图片评测集 | 校准 800 张，测试 1200 张，退化 800 张 | 10 个生成器家族。发现元数据捷径（AUC 0.969）后两侧统一处理，降到 0.513 |
| 视频盲测集 | 校准 63 条，测试 146 条，转码 120 条 | 8 个生成器家族。和选模用过的 12437 个文件按哈希比对，没有重复 |
| 换脸盲测集 | 150 对图片 | 3 种换脸方法。看成绩前定好规则：原始文件是主结果，统一编码副本只作对照 |

采集时不看模型分数。校准划分定边界，test 冻结后只跑一次。

### 8. 发现并修好图片公式

视频上训练的 C38 原头在图片上基本失效（校准集 AUC 0.59）。图片改用 `0.5 × 重训头 + 0.5 × CF384`，校准集 AUC 从 0.865 升到 0.909，不需要新训练。这是在校准划分上定的，test 没有参与。

### 9. 产品和报告改成 AIGC 口径

界面、报告、自检全部改成 AIGC 口径：结果页有总体档位和三路分档、逐帧分数图、人脸裁剪图、文件标识页；报告先写总体结论；没有人脸时身份比对显示不适用，不再算失败，这类视频的耗时也从 145 秒降到 31 秒；视频支持 WEBM，超过 90 秒按时间点取帧，解码失败转容错模式。

### 10. 运行环境可以一键重建

三个 Python 环境和 FFmpeg 不进仓库，`搭建环境.bat` 按锁定版本下载，每个文件校验 SHA-256，先构建再替换，校验不过不会破坏旧环境。

### 11. 独立代码审查和修复

做了一轮代码审查，修掉 9 个问题，包括常驻进程遇到异常会退出、超时后迟到的结果会覆盖已进证据清单的文件、历史表把总体档位配上整图分数、没装 Git LFS 时模型仍显示就绪等。

真实界面走通和全新克隆时又发现并修掉 3 个问题：启动脚本里的中文引号导致无法启动；双击搭建环境时脚本找不到自己的目录；没有人脸的任务被记成部分完成。

报告和证据导出做了一次独立验收，发现清单为空或缺哈希时仍提示“全部一致”，也已修复并补了测试。

### 12. 文档和申报材料

写了使用说明、研究报告、测试报告、架构说明、第三方清单、申报材料草稿，所有报告里的数字都从评测汇总自动填入。

## 三、现在的效果

模型、公式和边界冻结后只跑一次的盲测：

| 测试 | AUC | 真实样本误报 | 生成样本检出 |
| --- | ---: | ---: | ---: |
| 图片盲测（1200 张） | 0.886 | 7.8% | 65.7% |
| 图片传播退化（800 张） | 0.812 | 9.2% | 55.8% |
| 视频盲测（146 条） | 0.922 | 15.9% | 76.6% |
| 视频统一转码后（120 条） | 0.917 | 10.0% | 71.7% |
| 换脸补充盲测（300 张） | 人脸分支 0.663 | 14.0% | 36.0% |

误报和检出指总体档位进入“需人工复核”及以上的比例。

要如实讲的几点：

- **视频盲测集有元数据捷径。** 只看时长 AUC 就有 0.960，所以要同时看转码后的结果。
- **部分生成器漏检明显。** 图片上 flux.2-klein-9b 只有 17.5% 进入复核及以上。
- **换脸是最弱的一环。** 补充盲测上大约三分之二的换脸图进不了复核。选模时看过的高清换脸 AUC 有 0.895，低清视频只有 0.587，说明这部分很不稳定。
- **边界会漂移。** 名义误报 5%，图片盲测实际 7.0%。

完整数据见 [测试报告](测试报告.md)。

## 四、成果在哪里

| 内容 | 位置 |
| --- | --- |
| 代码、权重、图库、文档 | GitHub 公开仓库 `aigc-forensics` 和本机仓库各一份，两边相同 |
| 模型权重和图库 | 仓库里走 Git LFS |
| 评测结果 | `文档/评测/`：汇总、逐样本分数、清单、构建脚本 |
| 评测数据本身 | 只在本机（图片 7 GB、视频 1 GB），许可不适合再分发，可以用构建脚本重新下载 |
| 运行环境 | 不进仓库，用 `搭建环境.bat` 重建 |

**两份备份的核对：**

- 本机和 GitHub 的提交哈希相同，提交哈希本身就校验了全部内容。
- GitHub 上的 263 个 LFS 文件（2.32 GB）用批量接口逐个确认存在且大小一致。
- 从 GitHub 克隆代码、从零重建环境后，全部测试和自检通过。这次因为网速慢，LFS 文件是从本机复制后校验的，没有从 GitHub 整包下载一遍。

## 五、还没做或需要决定的事

- **换脸盲测还不够强。** 现在只有 300 张图片，人物身份分组不完整，没有视频。可以补人物元数据和换脸视频，让这部分结果更可信。
- **身份库和素材库的照片没有授权记录。** 公开仓库里只用于演示和研究。对外展示前，建议换成有授权的照片。
- **部分权重和数据限非商业研究。** InsightFace 模型、C38 来源链（R-UDA）、OpenFake 等，详见第三方清单。仓库没有附开源许可证，代码版权保留。
- **没有在第二台电脑上测过，也没有用真实案件材料测过。**
- **效率还能提高。** 每个图片任务都要重新加载一次人脸检测模型，批量时每张多花几秒。
