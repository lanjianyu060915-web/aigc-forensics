# 图片评测集说明

系统要支持图片，但原有图片数据基本都是人脸换脸类，所以单独搭了这个通用 AIGC 图片评测集。图片本身不随仓库分发，这里保留清单、构建脚本和逐样本分数，可以按固定版本重新下载和复核。

## 数量

| 划分 | 真实 | 生成 | 用途 |
| --- | ---: | ---: | --- |
| calibration | 401 | 399 | 定图片公式和分档边界 |
| test | 599 | 601 | 公式和边界冻结后只跑一次 |
| test_degraded | 400 | 400 | test 里真假各 200 张母图的传播退化版，同样只跑一次 |

## 来源

全部来自 [OpenFake](https://huggingface.co/datasets/ComplexDataLab/OpenFake) v2，固定提交 `3247b942f18d39d1fd476b1077852af033d35d8c`，获取日期 2026-11-04。汇编许可是 CC-BY-NC-4.0，底层图片的授权没有逐张核实。

- 真实侧：DOCCI、ImageNet、Pexels 各约三分之一，都经 OpenFake 分发。
- 生成侧：10 个家族、18 个模型字符串（FLUX、Z-Image、GPT-Image、Midjourney、Stable Diffusion、Recraft、ERNIE、Seedream、Imagen、DALL-E），单一家族不超过 20%。模型名是上游声明。

没有采用 Defactify 和 ELSA_D3，因为许可说不清。Community Forensics 的训练集和 CIFAKE 按任务要求排除。

## 防捷径

原始文件里真实图全是 JPEG，生成图大量是 PNG，分辨率也明显不同。只用宽、高、格式、文件大小训练的决策树，在 test 上 AUC 就有 **0.969**，直接评测没有意义。

所以两侧做同样的处理：EXIF 转正、转 RGB、居中裁切并缩放到 512×512、JPEG q95（4:4:4）、去掉元数据。处理后同一基线的 AUC 降到 **0.513**。这只排除了元数据的明显可分性，不代表没有别的捷径。

## 抽样和划分

- 固定种子 `20261104`，按 `SHA256(种子:row_id)` 排序抽样，选样和处理都没有看任何检测模型的分数。
- 按 SHA-256、解码像素和感知哈希去重。
- 相同提示词或描述归入同一组（共 1993 组），按组划分，calibration 和 test 没有跨组。

## 局限

- 只取了 OpenFake 两个分片的样本，不是整个数据集的随机代表。
- 内容不完全匹配：生成侧人物和插画更多，ImageNet 抽样里动物偏多。按人脸检测，真实图只有约 8% 有人脸，生成图约 50% 有。测试报告里把有人脸和没人脸的样本分开列。
- 统一处理后图片都是 512×512 的 JPEG，和真实办案材料的分布不同。
- ImageNet 同时是 CommunityForensics 的训练来源之一，存在来源级重叠，没有做样本级排查。
- “真实”是上游标注，没有逐张做摄影原件取证。
