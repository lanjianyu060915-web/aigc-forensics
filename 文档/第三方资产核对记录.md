## 3. 需要保留的条款及发布材料缺口

1. **FFmpeg 不能一概标为 LGPL。** gyan.dev 页面说明常规 builds 是静态 GPLv3，另外的 supplementary tools 才有 LGPLv3 说明。本地 `-version` 包含 `--enable-gpl --enable-version3 --enable-static`，`-L` 明确 GPL-3.0-or-later。GPLv3 §4、§5、§6 涉及声明、修改说明及传播非源码形式时的 Corresponding Source；§6(d) 对网络下载方式规定对应源码访问安排。本次只在独立 FFmpeg 目录见到两个可执行文件和来源 JSON，未见许可文本或对应源码交付材料。滚动二进制 URL 和哈希不能证明对应源码已提供。本报告不认定整个项目与该构建的法律关系。
2. **InsightFace 软件和模型是两类条款。** 代码 MIT，预训练模型限非商业研究，手动／自动下载同样适用。已分别读取 v0.7 和当前政策；当前政策也单列 `buffalo_l` 的许可联系事项。未取得项目的额外授权或独立再分发协议，不将公开模型包当作任意用途许可。
3. **ViF 的 CC BY 4.0 不是底层视频豁免。** 作者固定 README 明确要求继续遵循 Kinetics、Panda、HD-VILA 条款。Panda 自定义许可限非商业研究，并链接 HD-VILA R-UDA。R-UDA §2.1 对数据和 Results 的商业产品／服务用途有限制，§5.5 包含训练模型；§3 允许满足条件的再分发，不应误写为绝对禁止再分发。项目不分发数据是自身交付选择。
4. **Community Forensics 模型与数据不能混写。** 两个固定模型卡均声明 MIT，代码 LICENSE 也为 MIT；数据卡却同时写 CC BY 4.0、研究用途限定和生成器各自许可。保留这一原文组合，不自行裁定其效力或兼容性；逐生成器元数据没有全量审计。
5. **GenVidBench 的仓库许可证与数据声明不同。** README 数据声明为 CC BY-NC 4.0，根 LICENSE 是 Apache-2.0。数据清单保留前者，并明确后者不替代数据许可。当前 HF 入口缺少数据卡；没有用搜索引擎缓存中的旧卡推断当前内容。
6. **SWAN-DF 不是无条件开放数据。** 作者机构的 Zenodo v1 记录写明受 EULA 管理、严格非商业研究、文件访问受限。完整 EULA 及项目授权记录未取得；没有登录或申请，也没有推定网页演示样本可再分发。
7. **DFDC 的协议仍有缺口。** Meta 官方页只能确认 Preview／Full 区别、论文引用要求和访问前置条件；DFDC 入口只有 JavaScript 提示，Kaggle 规则未返回可读正文。没有从镜像数据卡或演员授权描述推断完整数据许可。
8. **冻结分支不能遗漏 ImageNet 基底。** 推理不下载预训练资源，与训练时是否使用过预训练是不同问题。包内源码支持后一事实；torchvision README 明确提示预训练模型可能受训练数据条款约束。ImageNet 原始条款入口未成功读取，因此保留“未核实”。
9. **许可原文随包情况不足。** 已在部分 `dist-info` 找到许可证、第三方声明和内嵌组件许可；应用 insightface、onnxruntime、streamlit 的 `dist-info` 抽查没有独立许可证文件，冻结 streamlit 同样缺少。onnxruntime 包目录另有 `LICENSE` 与 `ThirdPartyNotices.txt`，不能因 dist-info 缺少就断言整个包都没有。完整收集应同时检查包目录和发行包，当前清单不构成“全量许可证齐备”证明。
10. **示例图片仅披露真实现状。** 三处目录均按任务给定的来源说明写入，数量已枚举复核。未保留来源／授权记录这一缺口不能靠“不用于商业”或“异议后移除”转写为已授权。
