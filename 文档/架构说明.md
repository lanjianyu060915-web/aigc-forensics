# 架构说明

## 一句话

一个产品、三个检测分支、三层溯源。三个检测分支，其中两路定结论，一路只作提示。界面和任务编排来自原来的换脸鉴伪系统，通用生成内容检测来自团队的视频检测项目，两边都以独立进程接入，互不影响运行环境。

```text
                     上传图片或视频（文件固化到任务目录，记录 SHA-256）
                                       │
        ┌──────────────────────────────┼──────────────────────────────┐
        │                              │                              │
   文件标识解析                    AIGC 鉴伪                       素材与身份
  元数据与画面文字                     │                       （库内比对，可选）
        │        ┌───────────────────┼───────────────────┐          │
        │   通用 AIGC 分支          人脸分支             整图分支    原始素材检索
        │  C38 + 重训头 + CF384   CF384 打人脸裁剪图    CF384（整图）  全局特征粗排
        │  图片：1 帧 × 5 裁剪    视频：关键帧里的脸    冻结裁剪模型    + SIFT/RANSAC
        │  视频：10 帧 × 5 裁剪   图片：检测一次        （小图）      人脸身份比对
        │       + 4 帧 CF                                             InsightFace
        │        │ 主结论            │ 最多抬一级          │ 只作提示       │
        │        └────────────── 总体档位 ────────────────┘               │
        │                只由各路档位推导，分数不相加                      │
        └───────────────────────────┬──────────────────────────────────┘
                                    │
                 结果页、统一报告（JSON/TXT/HTML/PDF）
                                    │
                       证据清单（SHA-256）→ 证据包
```

任务结束时先生成报告，再建立证据清单，成功写入的原版 PDF 纳入清单。报告页面还提供后续人工复核：

```text
final_report.json ──→ 原版 PDF ──→ artifact_manifest.json ──→ 证据包
        │
        └── 当前报告 SHA-256 + 人工意见 ──→ review_records.jsonl ──→ 证据包
        │                                           │
        └───────────────────────────────────────────┴──→ 内存生成复核版 PDF，供下载
```

旧任务缺少 PDF 时也可现场生成下载内容。原版报告和机器结果不回写，复核记录单独追加保存。

## 运行环境

三个 Python 3.12 便携环境互相隔离，由进程边界分开，依赖不会冲突：

| 环境 | 跑什么 | 主要依赖 |
| --- | --- | --- |
| `python_runtime` | 界面、编排、身份比对、素材检索、文件标识、离线 OCR 和 PDF 报告 | streamlit、insightface、onnxruntime、opencv、reportlab、rapidocr-onnxruntime |
| `packaging_v0.4/resources/portable_python_v2` | 整图 ViT 检测 | numpy、Pillow、onnxruntime |
| `engine_runtime` | 通用 AIGC 引擎 | torch、transformers、timm |

`tools/setup_runtime.ps1` 按锁定版本重建这些环境。FFmpeg 放在 `系统/ffmpeg`。

PDF 使用 ReportLab 和随程序分发的常规、粗体静态中文 TTF 字体，不依赖浏览器或系统字体。ReportLab 版本和 wheel 哈希进入应用环境锁文件，环境搭建与检查沿用现有机制。

## 一次任务怎么走

1. 把输入复制进任务目录。图片存成 `query.jpg`（字节不变），视频存成 `query_video.*`。
2. 文件标识解析。这一步很快，所有任务都做，失败不影响其他模块。
3. 视频任务抽帧、选关键帧，首要帧存成 `query.jpg`。需要鉴伪时，对图片或视频首要帧及最多四个关键帧运行离线 OCR，单独保存文字线索；整个模块超时三十秒时记为未完成。
4. 鉴伪模块：先跑整图分支（视频按关键帧聚合），再裁人脸，然后跑通用 AIGC 分支（视频用整段文件）和人脸分支，合并结果。
5. 身份比对、素材检索（视频用关键帧）。身份主脸检索完成后复用已加载模型，按面积追加其他脸的前三候选，包括主脸最多三张；单脸不增加搜索，视频仅首要帧追加逐脸结果，原逐帧聚合不变。
6. 写统一结果与 JSON、TXT、HTML 报告，生成中文 PDF。报告写完后生成逐文件证据清单，将成功生成的 PDF 一并收录。

PDF 生成异常在报告模块内部记录警告，不把已经完成的任务改为部分成功，其他三种报告照常生成。下载旧任务报告或复核版时只在内存渲染，前端不回写任务中的原版报告。

任何一路失败都收成结果里的错误信息，其他部分继续。模型常驻服务不可用时自动改用隔离子进程，结果相同，只是要重新加载模型。

## 结果文件

| 文件 | 内容 |
| --- | --- |
| `detection_result.json` | 鉴伪结果。原有字段保留，新增 `general_aigc` 和 `overall` |
| `general_aigc_result.json` | 通用分支的完整结果，含逐帧逐裁剪分数；人脸分支在 `face_branch` 下 |
| `face_crops/` | 人脸分支用到的裁剪图和 `crops.json` |
| `file_provenance_result.json` | 文件元数据标识解析结果 |
| `visible_label_result.json` | 画面文字识别的判定、文字命中、原图位置、耗时及局限；独立进入证据清单 |
| `identity_faces/` | 逐脸查询副本与缩略图；缩略图进入证据清单 |
| `identity_result.json`、`source_result.json` | 身份、素材检索结果；身份新增 `faces` 与 `face_search`，保留主结果字段 |
| `artifact_manifest.json` | 任务结束时证据文件的路径、大小和 SHA-256，包含成功生成的原版 PDF |
| `final_report.json`、`检测结果_*.txt`、`检测结果_*.html` | 统一结构化报告和文字报告 |
| `检测结果_*.pdf` | 任务结束时生成的中文研判报告，包含图片、图表、用途声明和空白复核栏 |
| `review_records.jsonl` | 后续追加的人工复核记录，含复核人、档位意见、人工判断、依据候选快照、可选目标脸、记录时间及原报告 SHA-256；随证据包收录 |

`检测结果_任务编号_复核版.pdf` 是点击导出时在内存生成的文件，不覆盖任务目录中的原版 PDF。复核记录只追加；复核人姓名是手填的，没有账号认证，记录时间不是可信时间戳，也不构成不可篡改存证。

报告仅读取任务目录内的相对图片路径，任务目录搬动后可继续导出。图片缺失时保留文字和占位说明；进入 PDF 的文件名、复核意见等文字先转义，再排版。总体档位仍取解释字段中的 `technical.overall`，不重新推断机器结论。

## 档位证据强度和提示

`tools/research/build_band_evidence.py` 从五组已有评测汇总生成 `decision/band_evidence.json`，保留来源文件 SHA-256。编排在总体档位产生后通过 `aigc_evidence.py` 追加 `overall.band_evidence` 和 `overall.hints`；界面、解释和报告使用同一份说明。

短边不超过 256 像素触发低分辨率提示；文件标识提示生成而总体档位为证据不足时触发复核提示。统计文件缺失或字段不全时返回空结果。模型、融合公式、分档边界、总体规则和旧结果字段均保持原样。

## 配对对比与案件库

素材检索完成后，由 `source_upgrade.py` 调用 `pair_integration.py`，对前三候选逐一执行冻结的 `modules/pair_compare/pair_compare.py`。模型实例和查询预处理可复用。其输入、分数和结果与原检索分别保存，不改变原有排序、总体档位和任务成功状态。

当前为人工比对模式：`pair_compare.conclusion_enabled` 为假，`forgery_type` 为空。公开结果只保留对齐状态、对应框、相似度、区域差异数值和图像产物；实验分类标签不进入公开 JSON、报告或界面。视频限定首要帧及对应时间点。未启用自动类型规则，不生成身份绑定；逐脸身份候选独立提供给人工复核。

`case_libraries.py` 检查库内引用边界并调用现有索引。素材缓存由库根目录和内容清单摘要共同隔离，避免不同位置同名库或保留修改时间的内容变更误用旧特征。任务报告保存本次实际库快照；旧建库记录与当前内容不符时不沿用建库时间。`pair_compare_result.json`、`pair_compare/` 中的图片及数值文件均纳入原有证据清单。

## 其他设计取舍

- **不合并各路分数。** 跨域融合试过，外部集 AUC 从 0.898 掉到 0.439。各路分别标定，总体档位只由档位推导。
- **总体档位怎么定。** 通用分支定主结论。人脸分支提示风险时：通用分支是证据不足，抬到需人工复核；通用分支是需人工复核且人脸分支是高风险，抬到高风险提示。通用分支不可用时，人脸或整图分支单独最高只到需人工复核。没有人脸时人脸分支不参与。
- **整图分支不影响总体档位。** 它的边界只在高清人像上标定过，普通真实视频里 63–81% 都会触发高风险，DFDC 真实视频 AUC 只有 0.52。结果页仍然展示，只作提示。
- **图片和视频用不同的融合公式。** C38 原头是在视频帧上训练的，在图片校准集上 AUC 只有 0.59，真实图中位分就有 5.1。图片改用 `0.5 × 重训头 + 0.5 × CF384`，校准集 AUC 从 0.865 升到 0.909，不需要新训练。
- **人脸分支只抬一级。** 它用同一份 CF384 权重打人脸裁剪图，比打整图更能发现换脸（案例 3：0.89 对 0.66；补充盲测：0.66 对 0.61），但跨数据集不稳，所以不能单独给出高风险。
- **只给档位，不给真假结论。** 边界是真实样本分数的分位点，含义是“这个分数在真实样本里有多少见”。
- **进程隔离而不是合并依赖。** 界面环境、ONNX 环境和 torch 环境版本不同，强行合并没有好处，一个模块崩溃也不会拖垮其他模块。
- **文件标识不进入检测档位。** 标识可以伪造也可以被抹掉，单独呈现，由使用者结合判断。
- **生成器溯源没有做成功能。** 用现成特征做线性分类，同一数据集内 19 个生成器准确率 37%，换一个数据集的 Kling 只认对 6.5%，不足以作为结论，详见评测文档。


## 补充证据的边界

人工类型判断仅写入只追加的复核记录及复核版 PDF，不改机器结果中的 `forgery_type` 和关闭的 `conclusion_enabled`。原版 JSON、PDF、任务结束时的证据清单不因复核改写；复核报告摘要不一致时醒目提示。

逐脸开放集判定调用现有 `decide_identity_open_set`，阈值不变，也尚未针对逐脸场景单独验证。主脸低可信而其他脸有高可信候选时只增加界面提示，不改变总体档位和证据矩阵。

离线 OCR 的模型随固定 wheel 分发，运行时不联网下载。依赖及传递依赖进入哈希锁，由既有环境脚本重建。识别先将画面最长边限制为 1600 像素；在这张工作图上扫描整图，并把四角各占长宽 30% 的区域放大两倍后补扫，最后把文字框映射回原图坐标。通用字样归为 `visible_label_found`；工具名的字框中心仅在画面四周 15% 范围内时归为 `tool_hint_found`。只有通用字样与低档组合触发 `visible_label_conflict`，不改变档位。OCR 词表是未充分验证的起点，合成文字测试只说明受控字号与压缩条件下的可读性。
