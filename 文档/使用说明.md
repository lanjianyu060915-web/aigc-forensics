# 使用说明

本系统用于图片、视频的 AIGC 风险筛查和来源线索检索。检测和检索在本机运行；可配置大模型接口辅助研判及报告撰写。结果只作侦查线索和辅助研判。

## 第一次使用

需要 Windows 10 或 11，磁盘空余 15 GB 以上。有 NVIDIA 显卡时通用 AIGC 分支会用显卡，没有也能跑，只是慢一些。

1. 安装 [Git LFS](https://git-lfs.com/)，运行 `git lfs install`，再按[项目首页](../README.md)的克隆说明下载仓库。权重和图库都走 LFS，没装 LFS 拿到的只是占位文件。

2. 双击 `搭建环境.bat`。脚本按锁定版本下载三个 Python 环境和 FFmpeg，再解压冻结模型的运行环境，全程校验 SHA-256。有 NVIDIA 显卡时下载约 3 GB、装好后约 5.5 GB，没有显卡时走 CPU 版，小得多。网络中断可以重新运行，已下载的文件不会重复下载。

3. 双击 `运行自检.bat`。它用内置示例真实跑一遍全部模块，全部显示“通过”才说明系统可以正常使用。第一次要建身份索引和素材特征缓存，可能要几分钟到十分钟，之后就快了。

**安装目录尽量短**，避免多层嵌套，不要超过 60 个字符。路径太深时 Windows 写不出部分证据图，启动窗口和自检都会提示。

## 启动和退出

双击 `启动系统.bat`。会弹出一个黑色窗口，就绪后浏览器自动打开页面。这个窗口要一直开着。默认端口 8767，被占用时自动换一个，黑色窗口里会显示实际地址。

退出时点页面左下角的“关闭系统”，或者直接关掉黑色窗口。

模型服务要约 2 分钟才能就绪，左下角显示“运行中”后再分析最快。没就绪时也能分析，只是每次要重新加载模型。

大致耗时：图片约 1 分钟，没有人脸的短视频约 30 秒，有人脸的视频约 2–3 分钟。

## 分析一张图片或一段视频

1. 左侧选“新建研判”。
2. 把文件拖进上传框，或点“选择文件”。图片最大 20 MiB（JPG、PNG、WEBP），视频最大 200 MiB（MP4、MOV、AVI、MKV、WEBM）。也可以在下拉框里选一个内置示例。
3. 确认右侧的文件信息和 SHA-256。
4. 点“一键综合分析”，或者只跑其中一个模块。页面显示实时进度。
5. 完成后先看“研判总览”最上面的研判要点，再按需要看各页。

## 怎么读结果

系统分别回答四个问题，结果并列展示，**不合成总概率**。

| 问题 | 看哪一页 | 看什么 |
| --- | --- | --- |
| 是不是 AIGC 生成或换脸 | AIGC 鉴伪证据 | 总体档位：证据不足 / 需人工复核 / 高风险提示 |
| 文件和画面有什么标识线索 | 文件标识 | 元数据声明、容器结构和生成工具痕迹；另列画面文字识别 |
| 原图可能是哪张 | 原始素材溯源 | 四态结论：高可信候选 / 证据不足 / 库中未发现可靠候选 / 本次无法比对 |
| 这张脸更像库里的谁 | 人脸身份比对 | 同样的四态结论，只在画面有人脸时有意义 |

### 总体档位怎么来的

三个检测分支，其中两路定结论，一路只作提示。各自分档，总体档位按下面的规则推导，分数不相加：

| 情况 | 总体档位 |
| --- | --- |
| 通用 AIGC 分支有档位 | 以它为主结论 |
| 通用分支是证据不足，人脸分支提示风险 | 需人工复核 |
| 通用分支是需人工复核，人脸分支是高风险 | 高风险提示 |
| 通用分支没有档位（比如运行失败） | 看人脸分支；再没有才看整图分支。单路最高只到需人工复核 |
| 整图分支提示风险，其他两路没有 | 不改变档位，只在理由里提示 |

### 容易读错的地方

- **分数不是概率。** 分档边界是真实样本分数的 p95 和 p99，含义是“这个分数在真实样本里有多少见”。
- **“证据不足”不等于真实。** 只说明模型没有发现足够的风险信号。换脸尤其容易漏，低清视频上基本检不出来。
- **“高风险提示”不等于造假。** 高清真实人像、强后期的真实图都可能进高风险，要结合文件标识和素材检索判断。
- **有标识是线索，没有标识不说明任何事。** 标识可以伪造，也可以被转码、截图抹掉。C2PA 只检测结构，不验证签名。
- **“高可信候选”不等于确认。** 身份和素材都只在当前库内比较，库里没有的人或图不可能被找到。

## 画面文字标识

“文件标识”页把元数据声明与“画面文字标识”分开列出。选择“一键综合分析”或“AIGC 鉴伪”时会运行离线文字识别：图片读取当前查询图，视频读取首要帧及最多 4 个关键帧。结果显示识别文字、位置和识别置信度；置信度不是内容真伪概率。

通用“AI 生成”等字样可形成文字线索；工具名的字框中心只有位于画面四周 15% 范围内才算提示，中央的工具名不作为标识。初始词表尚未在真实工具输出上完整验证。没识别到不代表不是生成内容；字样可以被添加、裁掉，或被压缩到认不出。这里只是文字识别，不核验来源。

文字识别未完成时会单独说明，其他模块继续。识别到通用 AI 字样而总体为“证据不足”时会提示人工复核，检测档位保持不变。

## 批量研判

左侧选“批量研判”，一次选多张图片（最多 100 张，不支持视频），勾选模块后开始。系统逐张串行分析，结果汇总成一张表，可以导出 CSV。某一张失败不影响其他图片。每张图的完整证据都保存为独立任务，可以在“历史任务”里打开。

## 大模型设置与上传范围

左侧“大模型设置”可填写兼容接口地址、模型名和密钥，并选择研判方式与上传范围。保存位置为本机 `用户数据/profile/llm.json`，不进入源码仓库或任务证据包。密钥输入框只写不读，留空保留原值，保存后只显示是否已设置；“测试连接”发送一条不含案件信息的请求。

接口、模型和密钥分别优先读取 `AIGC_LLM_BASE_URL`、`AIGC_LLM_MODEL`、`AIGC_LLM_API_KEY` 环境变量，没有时才用用户配置。环境变量已设置时，此页保存值不会覆盖它；设置系统环境变量后应重新启动程序。“系统状态”会显示接口主机、模型、研判方式、上传范围、研判是否带图及人脸后端，不显示密钥。

| 服务 | 接口地址填写示例 | 使用说明 |
| --- | --- | --- |
| 阿里云百炼北京 | `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | 将业务空间编号替换为控制台提供的值，地址须与密钥所属空间和地域对应；本轮调用模型为 `qwen3.8-max` |
| 百炼原北京通用域名 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 官方仍保留；空间密钥鉴权失败时，应自行核对控制台地址，程序不尝试其他地址 |
| DeepSeek | `https://api.deepseek.com` | 仅为官方兼容地址填写示例，本轮未验证其思考参数、多模态与严格结构化输出组合，不自动切换到该服务 |
| 本机兼容服务 | 如 `http://127.0.0.1:8000/v1` | 地址由本机部署者提供；本轮仅使用模拟服务验证本机地址接线，未部署本地大模型 |

地址末尾不加 `/chat/completions`，程序会自动补齐。外部接口说明依据[阿里云官方兼容文档](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)和[DeepSeek 官方接入文档](https://api-docs.deepseek.com/)，服务商配置可能变化，以对应控制台为准。

`full` 上传图件和完整结构化结果；文件名、候选名和人员编号保留，本机路径移除。`text_only` 只上传去除文件名、任务编号、摘要、库名及人员名等标识后的结构化结果，任何调用都不附图片；代号映射保存在任务本地。PDF 仍会嵌入本机原图。开始单张或批量研判前，页面显示实际范围。

研判方式为“规则研判”时，最终档位仍用原规则；接口已配置时，大模型仍可参与报告撰写，因此也适用上传范围。接口未配置时使用本地模板。大模型研判最多调整一档，并受固定证据下限约束；接口失败或输出校验不通过时回退规则，分数为空，报告保留原因，不自动换模型。

“研判评分”是分档内的可疑程度表达，不是伪造概率，也不与检测模型分数相加。检测没有可用档位或前置解码失败时显示“无法完成判断”，不能当作低风险。所有模型文字仍须人工阅读与复核。

## 逐脸检测与定档口径

图片和视频关键帧按面积最多展示八张脸的裁剪、位置、分数、尺寸和定档参与情况。短边小于64像素时明确提示结果不可靠。最高分人脸会标出，但最高分不一定参与本次定档。

默认仍为原人脸后端与 `largest`：每帧沿用原最大脸的分数，视频对帧分数取算术平均。为恢复第二版结果，这条兼容路径保留原40像素接纳门槛，40–63像素仍标注不可靠。实验性 `max_all` 对每帧符合64像素门槛的脸取最高分，再按帧平均；不能把全部人脸混在一起平均。

新增后端和聚合策略必须先完成对应来源的误报与检出验证，再按固定门槛决定是否作为默认；不同后端的分数和分界线不能混用。报告只有找到匹配后端与口径的统计时才引用，否则显示“无对应统计”。

## 档位证据强度和提示

总体结论下方增加档位证据强度表，列出当前档位在图片、图片传播退化、视频、视频统一转码和换脸五类测试中的真实、伪造样本数及比例之比。样本不足 10 的单元格标注“样本少，只能看个大概”。这是测试集参考，不是本案概率，也不是正式的似然比。

输入短边不超过 256 像素时显示低分辨率提示。文件标识提示生成、疑似生成或生成工具痕迹，而总体档位为证据不足时显示复核提示。两类提示不修改检测档位。总体档位为证据不足时，还会提醒约三分之二的换脸测试图落在这一档，不能据此排除伪造。

旧任务没有这些字段时照常显示原报告；统计文件缺失不影响检测运行。

## PDF 研判报告和人工复核

启用第三版研判配置的新任务结束时，自动保存 `研判分析报告.pdf`，原模块结果另存为 `技术明细报告_任务编号.pdf`。未启用研判配置的旧流程仍使用 `检测结果_任务编号.pdf`。主报告解释材料固定、文件标识、画面文字、三路检测、素材与身份候选及线索组合，并附图件、过程记录和局限。每页都有任务编号和页码。

在报告区域点“导出研判分析报告（PDF）”下载主报告，也可单独导出技术明细。历史任务没有主报告时，可点“生成研判分析报告”，根据已有结果补生成；新文件写入该任务目录，原结果文件和原技术报告不变。重复打开或下载不会再次请求大模型。已有研判原件与输入或清单不一致时拒绝复用；重新分析应另建任务副本。

人工复核按下面的步骤记录：

1. 填写复核人，并在“对检测档位的意见”中选择相应意见。
2. “人工判断”默认是“未作类型判断”；也可选择倾向换脸、同地点的不同人、未改动副本、美颜或局部修改、生成内容，或无法判断。这些都属于人工判断。
3. 有素材配对结果时可选“依据候选”；有多张脸时可选“人工选定的目标脸”。脸编号沿用身份页显示，主脸另有标记，不应把候选排序当作脸编号。
4. 填写复核意见并点“追加保存复核意见”。系统记录时间、原报告摘要，以及所选素材候选的名称和摘要。
5. 导出复核版 PDF。首页显示最新人工判断，正文逐条列出记录，并注明“人工判断，非系统结论”。

复核人和意见均为必填。记录只能追加，界面不提供修改和删除。复核意见保存在 `review_records.jsonl`，不修改机器结果、`final_report.json` 或原版 PDF。研判复核版另存 `研判分析报告（复核版）.pdf`，追加人工意见章节及独立校验清单；技术明细复核版在页面内存生成。

复核人姓名是手填的，没有账号认证；这不是可信时间戳，也不是不可篡改存证。复核依据的报告摘要与当前报告不一致时会醒目提示。保存校验失败会保留输入；复核记录损坏时仍可下载已有原版 PDF。

如果 PDF 字体缺失或生成失败，页面会提示 PDF 不可用，TXT、HTML、JSON 报告仍可正常使用。PDF 导出失败不会改变已有检测和检索结果。

## 历史任务和证据固定

左侧选“历史任务”，可以看到所有做过的分析，选一个就能重新打开全部证据。打开任务后页面下方有“证据固定”：

- **校验证据完整性**：按任务自带的清单重算每个证据文件的 SHA-256，能发现文件被改动或缺失。
- **生成证据包**：把任务目录打成 zip，附文件校验清单，便于移交和归档。任务结束时成功生成的 PDF 计入原始证据清单，后续追加的人工复核记录也会收录进证据包。

分析结果保存在 `用户数据\runtime\tasks` 下，每个任务一个目录。

## 使用自己的身份库和素材库

在“新建研判”的“案件库”入口填库名称和目录路径：

- 身份库：一个目录，下面每个人一个子目录，子目录里放这个人的参考照片。
- 素材库：一个目录，里面放图片。

点击“检查案件库”查看文件数、无法解码、重复、无人脸和多人脸参考照片；点击“检查并建立索引”准备缓存，页面显示实际处理进度。身份照片直接放在人员子目录下，多层嵌套照片不能作为有效参考。库可以放在仓库之外，但库内引用和链接不能越过选定的根目录。

索引和建库记录保存在本机用户数据目录，不改动原始库文件。报告记录库名称、文件数、文件清单 SHA-256 和建库时间。库内容改变后需要重新建库；缺少与当前内容匹配的建库记录时，报告会明确写“未记录”，不沿用旧时间。

图片有多张人脸时，身份页保留**面积最大**的主脸结果，并按面积为其他脸追加候选，包括主脸最多 3 张；每张脸展示缩略图、前三候选及判定。单张脸失败不会影响其他脸。单脸不重复搜索，视频的逐脸候选只代表首要帧。

系统不判断哪张脸被改动，每张脸的候选都只是候选。主脸不一定是要查的人，可以在人工复核里选择目标脸。逐脸判定沿用现有阈值，尚未在这一场景专门验证；未处理到的脸可裁剪后单独复核。

## 人工配对对比

“原始素材溯源”页逐一展示检索前三候选的并排图、对齐滑动对比、差异热图和逐脸相似度。当前版本未给出伪造类型结论，也没有把身份检索结果绑定为“被修改的脸”。差异可能来自压缩、缩放或颜色变化，不能单凭热图或相似度判断制作方式。

对齐失败表示暂不能判断是否同源，不表示两张图必然无关；实际底图也可能排在前三名之后。无人脸时不作换脸判断。视频仅对首要帧做配对，页面和报告标出时间点，不能扩展为整段视频结论。

配对规则摘要不符或执行异常时保留其他模块的结果。 页面会显示“配对比对未完成”和脱敏原因；初始化失败且没有候选时也会提示。未运行会单独说明，不能把空候选当作已完成配对。已生成的对比图和数值文件进入任务证据清单，可在历史任务中复核。新功能关闭时不生成配对字段，旧任务仍按原格式显示。

## 遇到问题

| 现象 | 处理 |
| --- | --- |
| 黑色窗口一闪就没了 | 从命令行运行 `启动系统.bat` 看报错 |
| 页面左下方显示某模块“不可用” | 到“系统状态”页看具体缺什么；常见原因是环境没搭完或 LFS 文件没拉下来（`git lfs pull`） |
| 模型服务一直“启动中” | 等 2 分钟；还不行就点“重新检测 / 重试服务”。常驻服务起不来时分析仍能进行 |
| 分析卡住 | 任务按顺序执行，运行中不能取消。视频和首次分析本来就慢，看进度条是否在走 |
| 身份或素材第一次特别慢 | 在建索引或特征缓存，只做一次，搬动目录后可复用 |
| 提示 PDF 不可用 | 先使用 TXT、HTML 或 JSON 报告；检查运行环境是否完整，以及中文字体是否随程序下载齐全。已有原版 PDF 可直接下载 |
